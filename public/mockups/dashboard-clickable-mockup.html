Design notes — please confirm before Step 2

  • Top KPI row: already clickable today; Phase 4 changes the hrefs to Sean's exact spec — Active Leads now uses status_in=new,invited,contacted,engaged,sample_sent,quoted,nurture (not the open list), Samples Sent uses ?since=30d, Wins uses ?status=won&won_year=2026. The Leads page client needs to read status_in and won_year from the URL — Step 2 work.
  • "This Year" tiles: currently static cards; Phase 4 wraps each in a <Link> with the same styling as today, plus the hover tooltip and an "Edit ↗" badge that fades in on hover.
  • Tooltips: implemented as a small navy popover anchored above the card; appears on hover and on keyboard focus (accessibility). Each names its source table(s) so Sean can always trace a number to its query.
  • Schema additions (migration 018):
    • New manual_orders table (id, customer_name, customer_company, order_date, parts jsonb, total_revenue, source default 'manual', notes, lead_id nullable FK).
    • shipments.is_sample boolean (nullable). Backfilled true on existing rows — every CRM-side shipment has historically been a sample. Plus qty_6in / qty_11in integers (nullable) for the editable Parts column on the samples detail page.
    • leads.closed_won_at timestamptz (nullable). Backfilled for current won leads via MAX(activities.created_at where type='web_order'), with a fallback to last_activity_at. Phase 4 also wires the lead-detail "Mark as Won" handler to stamp this column on transition (currently only the status field updates — confirmed by reading updateLeadField + LeadDetailClient.tsx:179).
  • Detail pages: all four use the same shell — breadcrumb, summary cards (split + total), sortable table, optional "Add" button on Revenue. Inline edits on the Samples page use the same field shape as the Add Manual Order form.
  • Brand: navy (#1C2E4A) + red (#A52A2A) only. No new fonts. Card styling matches the existing dashboard exactly — same border, shadow, padding, hover feel.
  • Footer line: Step 6 adds the "Data as of {timestamp}; click any tile to see the source records" line at the bottom of the dashboard so Sean never wonders where a number came from.

Two open questions

  • Samples-shipped source. Today the dashboard's "Free samples shipped" tile reads orders where is_sample = true AND shipping_status = 'shipped' (Stripe-side $0 sample-form orders). Sean's spec says read from shipments (CRM-side LinkedIn samples). After migration 018 both tables have an is_sample flag. Recommendation: the detail page reads shipments per spec; the dashboard tile also moves to shipments so the count and the detail page agree. Confirm OK.
  • "Mark as Won" wiring. The lead-detail page currently flips status via updateLeadField('status', 'won') with no closed_won_at stamp. Step 2 adds a small server-side hook (or wraps the call) so the column gets stamped automatically on the win transition. Existing won leads are covered by the migration's backfill.
